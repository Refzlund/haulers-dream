## Current bounded implementation

Feature cards measure their complete name and blurb using native text measurement at their actual text width. A requested Tiny font may resolve to Small; both measurement and rendering use the effective native font. The card grows vertically, retaining one whole-card action, its original setting binding and its disabled behavior. The collect and filtered-render paths retain the same control ordinals and share the measured layout. A filtered-out control takes no layout or input.

The right-hand help panel retains the selected control or option document while the pointer crosses the gap and scrolls. The existing category/ordinal sequence identifies controls; matrix headers and row/option explanations have distinct subkeys. The real current draw traversal refreshes the complete selected title, body, value and optional graph even without hover. It does not combine independently retained strings or treat a captured graph delegate as an immutable value.

Help scrolling resets for a different final document, rather than for intermediate parent/option offers within the same event. It also resets when the native window owner or active category/query context changes. Search-header navigation ends its old traversal through the scroll-view cleanup before any later old-search controls or footer can run; the next real traversal supplies the new context's help.

Search keeps its existing scorer, grouping and maximum 30 results. Width, scale, language/effective font and the existing conditional control dependencies invalidate its geometry together. The live Common Sense foreign-gatherer note is included, so a paused external option change cannot leave downstream navigation positions cached at an old height. The new window state is explicitly nonserialized because profile capture includes private instance fields.

The modified measurement, card drawing and help drawing restore the text/color globals they temporarily change in finally blocks. Successfully begun content/help scroll views are ended even if their body throws. This does not claim to repair an exception occurring inside native BeginScrollView itself. Genuine native focus and mouse capture transitions are preserved.
