## Workstream and per-source contract

L01–L55 are the ledger's topic identifiers, not a claim of 55 discrete bugs. Each original source has its own acceptance reference(s), with separate fields for disposition, rationale and verification state. A single source may contain several behaviors and must be split further when investigation reveals distinct acceptance criteria. Duplication preserves evidence while avoiding inflated witness counts.

For every actionable behavior, the workstream must record:

1. Requested/expected behavior; source and reporter context; relevant version, settings, mods, pawn/map/job types.
2. Prior fix chain, including failed retests and withdrawn explanations; which mechanism or coverage was missed, or what evidence is still needed to determine that.
3. Concrete acceptance criteria and a discriminating reproduction/test; no boolean 'done' based only on a title or helper test.
4. Investigation with code and runtime/log evidence; design and alternatives considered.
5. Implementation, migration/default/translation/documentation impact, shared dependencies and regression risk.
6. A failing-before/passing-after result where reproducible, appropriate live-game evidence, independent QA, and fresh QA after corrections.
7. The exact source/binary/commit/settings/mod versions that passed. Later shared changes reopen invalidated evidence.

States: pending investigation → reproduction/design → implementation → verification → independent QA → integrated verification → complete. 'Blocked evidence' remains incomplete and records the specific missing prerequisite. Historical confirmed fixes require relevant regression evidence before being accepted as satisfied. Dispositions that reject/change a literal request require independently reviewed evidence and an explicit alternative or limitation; difficulty or backlog size is not a reason.
