# F12/F13 independent implementation-boundary review

`work_cadence_finish`, 2026-09-24. Recommendation accepted with the concrete refinements below. No product edit, build, Prepare, game launch or feedback refresh was performed.

The frozen C425-S03/S04 requests support explicit point-to-point hauling and a selected shelf. The existing acceptance records deliberately add total quantity, queue/interruption persistence, partial capacity and supported integrations. Preserve these. They do not require automatic replenishment rules or a generic logistics framework. The source still implements neither feature; this is not evidence of recurrence after an earlier exact-destination fix.

## First coherent authoring boundary

Implement **one actual saved selected-source → bare-cell hand-carry order**, including a real driver, bounded multiple trips, explicit blocked/Resume/Cancel state, current/queued save identity and native cleanup custody. The order model and physical backend should be one reviewable authoring assignment. It may be tested through its synchronized command entry before publishing the final targeter, but should not end as another unused state model or definition with no productive path.

A non-storage point does not need to wait for every shelf/provider allocator. It can use the existing native source and exact-cell reservation domain, with conservative physical observation and no steal. Do not create a separate explicit-haul reservation list. Reuse/extract the existing physical cell/stack observation records for this narrow bare-cell adapter; do not construct a fake SlotGroup or treat `FreeUnitsFor == int.MaxValue` as available space. Constrain this initial destination to genuinely non-storage cells, and revalidate that distinction on arrival. An existing storage point follows the exact-shelf/shared-admission extension, because it has real filters and competing inbound stock.

Immediate acceptance for this slice: 7 of 15 delivered at the exact bare cell; a real bounded multi-trip total; two distinct 7/9 orders at identical targets; queued and carrying save/restart; queue clear versus capture/restore; one interruption with real drop/merge; and cancellation after partial progress without losing cargo or resuming the canceled intent. This moves F12 materially without closing F12 or F13 prematurely. Add exact-shelf admission and publish the unified UI next; do not leave that dependency indefinitely assigned to unnamed infrastructure.

## Required refinements and risks

**Durable intent is separate from job and trip identity.** The proposed per-pawn monotonic order ID and scribed immutable source/map/destination/total are appropriate. Link current/queued native jobs by actual loadID, and verify the exact current driver at mutation boundaries. Native Job.Clone copies loadID and JobIsSameAs consults the cached driver's `IsSameJobAs` before its target-only comparison. Override the dedicated driver predicate; two new intents remain distinct even when targets/counts match. A missing or duplicate link pauses; it does not create another job. Allocate identities in the synchronized commit, never during local menu/target probes. Reconcile after all native cross-references/jobs exist, not while Saving or LoadingVars runs. Current pre-save exemptions for nearby and transporter orders are the correct semantic place for the additional positive identity predicate; no generic playerForced exemption is needed.

**Do not confuse queue cleanup with cancellation.** Native CaptureAndClearJobQueue copies wrappers around the same Jobs, then clears with canReturnToPool=false. Native SuspendCurrentJob enqueues the same Job before its cleanup. RestoreCapturedJobs can return later jobs directly to the pool after a failed earlier restore. A narrow exact-order capture/restore scope plus final reconciliation covers these paths. A generic QueuedJob.Cleanup postfix that marks every order canceled would fail the contract. Conversely, canceled tombstones must prevent stale callbacks/resume buttons from reviving an order. Native idle-job queue behavior need not be redefined: prove preservation behind real non-idle explicit work.

**Hands isolate normal personal stock, but do not solve interruption automatically.** Native CleanupCurrentJob runs driver Cleanup, clears the driver/current job, and only then performs its Near carry drop. Capture the exact piece before this boundary and reconcile after it, including actual receiver callbacks/quantity changes for a merge. A finish action alone cannot do this. Never credit a cleanup drop as delivery to the requested destination merely because the cells happen to match. Native save/resume must preserve original source history, actual owned remainder and accepted delivered units independently. If another consumer takes the recorded remainder, report the changed custody; do not find replacement same-def stock.

**Keep applies to existing personal inventory, not the explicitly selected floor parcel.** The first hand-carry path should not tag, spend, merge with, lower or replace existing kept/personal inventory. A chosen floor stack can be delivered even when the pawn keeps other units of that def. If recovery must use inventory, retain exact no-merge piece ownership; do not reuse GetHashSet's broad self-healing or generic inventory-surplus unloading as order authority. Record this invariant in the new command's tests rather than importing nearby's quantity-only retention oracle.

**Concrete native exception hazard in the proposed count-limited drop.** The installed `ThingOwner.TryDrop(thing, cell, map, mode, count, ...)` calls `thing.SplitOff(count)` into a private `thing2` when count is less than held stack size. It then calls placement and only reabsorbs on a normal false return; it has no finally recovery around a throwing callback. Therefore merely retaining the original CarriedThing and observing placedAction cannot guarantee ownership of a detached unplaced tail. The implementation must retain the exact attempted split before the throwing native boundary, or observe that exact split within a narrowly scoped operation. Do not add an unbounded global cargo recorder. If the native carry wrapper receives the whole known hands parcel, this hidden sub-count split is avoided; later partial-capacity attempts still need an explicit policy for count < held units. Preserve the original exception and reconcile verified receiver deltas once. A boolean false may coexist with real delivered units.

**No-steal needs a real reservation gate.** Installed ReservationManager.Reserve falls back to ignoring other reservations when job.playerForced is true and calls EndCurrentOrQueuedJob on conflicting claimants. Passing ignoreOtherReservations=false alone is insufficient. Use a positively identified new-order boundary that refuses the forced fallback, with normal native CanReserve/source count and exact job ownership checks. Do not toggle unrelated jobs' flags, reuse the nearby forced-storage scope or call InterruptCommittersTo. Ordinary native reservation takeover by a different explicit command is an interruption the new order must handle, not permission to retaliate by stealing reservations back.

## Exact shelf: a bounded shared integration, not a second ledger

The recommendation is correct that today's StorageClaimLedger/StorageCommitments cannot certify one selected shelf. Claims are per pawn/group/def, `StorageEvidence.Accumulate` folds same-def stock and keeps one knownGroup, and group capacity can be distributed among linked siblings. The new order must restrict allocation to the selected concrete parent and cells while sharing the canonical accounting identity. A lower-priority selected shelf is valid when its actual filters/capacity allow it; NearbyHaulCommand.CanOffer's automatic better-storage search cannot authorize it.

The next shelf slice should have one narrow admission operation owned by existing storage code: observe selected resources, reconcile relevant native/HD incoming cargo, acquire bounded vacant-slot/resident-deficit allocations, then retire exactly accepted units on placement or release the exact trip on cancellation. Extend existing StorageEvidence and native gate/count/claim lifecycle seams for the new dedicated job. Once detailed allocations represent an inbound parcel, do not subtract its old group row again. Do not add a second explicit-only dictionary whose occupancy automatic/native haulers cannot see. Keep queued/preflight probes read-only and acquire live allocations only for the actual current job/driver. Reacquire runtime allocations after load from saved intent/custody; persisted old capacity is not a live reservation.

Shared same-tick exclusion for the selected resources is necessary before shelf publication. A completed all-map universal allocator or unrelated billing/refueling work is not. Likewise, CargoPhysicalSession has no production caller and is not a mandatory prerequisite for a bounded exact-piece operation; reuse its contracts only where they simplify this concrete ownership problem. Named ASF/minified/quantity-rule profiles remain required follow-up integrations and must keep honest unsupported/blocked reasons until verified. Native shelf proof cannot close those profiles.

Before publication, retain selected-shelf movement/minification/map/identity checks, same-shelf alternate cells without linked-sibling substitution, actual 3-of-7 placement and retained 4, source growth/exhaustion, full/forbidden/destroyed destinations and mixed native/automatic/explicit competition. The complete menu/quantity/targeter, distinct MP endpoint, progress/Resume/Cancel, actor gates and translations belong to this feature's remaining work, not a reopened general UI project.
