Implement one **Haul to…** order with two destination types: an exact map cell or one concrete shelf. F12 and F13 share quantity, custody, queue and save behavior; two unrelated command implementations would duplicate the difficult parts. The first authoring slice should be the saved order and native job lifecycle, followed directly by its controlled hand-carry trip and destination admission. Do not add another investigation framework or expose a command whose destination still falls back to automatic storage.

## Recommended player semantics

Select one actor and a concrete spawned item, choose **Haul to…**, enter a total quantity, then select the cell or shelf. Capture actor/source/map and queue intent throughout. Cancel, stale selection or changed source during UI creates no order, job, reservation or cargo. A one-unit/nonstackable source bypasses the quantity slider. A forbidden source may be chosen deliberately as a forced order, matching existing manual pickup semantics; destination filters, actor permissions, forbidden destinations and other live claims still apply.

The quantity is the total, not a per-trip repeat: 100 means 35+35+30 at a 35-unit carry limit. Do not gather neighboring or replacement same-def stock. Source growth does not enlarge the request; source exhaustion/replacement retains delivered progress and a useful blocked reason. A bare point means that exact cell. A shelf means its concrete object and current member cells, never a linked sibling or a replacement at the same coordinates. Moving, minifying, despawning or changing its map pauses the order for explicit revalidation, with no automatic retarget.

Choose **no stealing of other live reservations** for the initial command. Player intent authorizes the selected destination, not cancellation of another actor's work. A full/temporarily unavailable destination leaves a visible blocked order with delivered/total progress and Resume/Cancel. Resume revalidates the same intent; no perpetual work-scan retry. Cancellation releases future capacity and hands actual remaining cargo to explicit recovery without counting it as delivered. Do not adopt unrelated inventory as recovery cargo.

## Smallest coherent code sequence

1. **Saved authority and lifecycle.** Add an `IExposable ExplicitHaulOrder` plus a small owner/helper, a deep-scribed list and monotonic per-pawn ID in the existing pawn component, and a dedicated JobDef/driver identity. Separate immutable source/map/destination/requested total from trip count, delivered units, phase/reason and actual owned pieces. Link only the actual dedicated current/queued job by recorded loadID/order ID; pooled Job references and unsaved driver fields are not durable authority. Different requests of 7 and 9 at the same targets must not be swallowed by native same-job deduplication. Allocate persistent IDs only in the synchronized command, not UI enumeration. No new order starts until its physical backend exists.
2. **Narrow native lifecycle integration.** Extend the existing pre-save identity exception and reconcile after cross-references resolve. Queue cleanup must distinguish cancellation from native `CaptureAndClearJobQueue`/restore and suspension: native capture copies wrappers around the same Job, while current cleanup runs driver cleanup **before** the subsequent carry drop. Observe the complete native cleanup boundary for cargo; a driver finish action alone is too early. Preserve terminal cancellation, pause ambiguous/missing links and never reconstruct a missing queued job speculatively. Keep unrelated job handling byte-inert.
3. **One controlled physical trip and shared admission.** Use hands for one bounded selected-source trip, avoiding personal-inventory merges. Revalidate actual current job/driver, source count/reservation, native carry/CE capacity and destination before pickup. Add the bare-cell projection adapter and exact-shelf resource restriction to the existing storage work. Canonical linked-group identity is for shared accounting; selected-parent identity restricts where this order may spend capacity. A def-wide claim, unknown `int.MaxValue`, or a new private explicit-only ledger cannot satisfy mixed native/automatic competition. Integrate resource admission with existing HD/native incoming-cargo accounting before publishing shelf support. Keep queued/preflight probes read-only.
4. **Direct placement and complete UI.** Retain the real split and hands owner. Use count-limited native Direct placement with receiver/count callbacks; never generic HaulToCell/PlaceHauledThingInCell fallback, duplicate collection or haul-aside. A false return after adding 3 to a 72/75 stack is still 3 delivered, with 4 of an attempted7 retained. Credit verified receiver deltas once and release the same accepted allocations; preserve partial progress and original exceptions. Continue bounded trips to the unchanged total. Then connect the menu/quantity/targeter, progress/Resume/Cancel, distinct synced endpoint and all 16 translations.

Authoring the persisted boundary can proceed while the shared allocator is completed, but the allocator/physical trip is the next required slice, not an optional future enhancement. This dependency is real in current source. Do not reopen completed F07/F11 controls merely because their patterns are reused; verify the new joins and new order semantics.
