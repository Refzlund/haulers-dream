# F04: actual settings rendering

`src/SettingsRendered.cs` is test-only source compiled into the existing private runtime host. Entry point: `HaulersDream.F04Native.SettingsRendered.Begin(Map, Check, Event, evidenceDirectory)`, followed by `Update()` each frame and `Dispose()` on termination. The explicit admitted case is `F04-SETTINGS`. It calls the real native `Dialog_ModSettings` and the selected product's settings implementation. It does not edit the product or deliver physical or synthetic input.

The finite scenario retains the normal 900×700 dialog and records actual screen, logical viewport and content geometry. It covers every active feature card in English at scale 1, English at the largest native-supported scale for the actual screen, and Italian keyed translations at that supported scale with `Prefs.DisableTinyText=true`. These are three focused views, not a locale/scale matrix. No physical display or resolution setting changes. At a screen whose maximum supported scale is 1, the first two views may coincide; the evidence reports this rather than claiming a distinct constraint.

Each view joins the actual feature catalogue to all 19 source slots (18 when Vehicles is absent), measures complete translated names/blurbs with native text metrics, checks current allocated boxes, and records text exceeding the old name-22/blurb-20/card-54 fixed layout. Programmatic scrolling exposes every active card completely across overlapping screenshots. If Vehicles is absent, a clearly labelled supplemental owned window renders its actual translated name/blurb through the real `FeatureCard` helper; this is text-layout evidence only, not Vehicles activation or compatibility.

The scenario renders an actual search result, navigates to the control with the tallest actual help body, selects its help identity once, then relies on normal native draws to retain it. It captures help at the top and after programmatic bottom scrolling, requiring retained help scroll and unchanged content scroll. Mouse-hover interference fails explicitly; the fixture does not reseed the document every frame or claim wheel/button input coverage.

Screenshots use native `ScreenCapture.CaptureScreenshot` after real Repaint and hold the view until a complete PNG is written. The root reviewer must decode and inspect the actual images together with all assertions, geometry, native errors and logs before closing F04. A compile or PNG file alone is insufficient. The 180-second timeout and terminal cleanup restore settings, keyed-language reference, UI scale, Tiny preference, original view state and time speed; only the two owned windows are removed. Native settings close writes the restored settings inside the already admitted private runtime.

The native API investigation is in `native-api.md`. This implemented scope follows the later supported-scale decision: there is no 760×650 stress window or broad capped-result matrix. The scoped keyed-language switch is not a full Def relocalization or game reload. Source authoring itself performs no build, game, controller or input action. Root reported the initial host compile passed with zero warnings/errors; actual rendering and independent source review remain pending at this author handoff.
