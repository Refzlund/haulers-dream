## Implemented

`TransporterUnloadState` owns saved unload intent and load-session provenance. Disabled/master-off flags are dormant, never active load blockers; disabling does not erase player intent. A successful fresh load or top-up clears every actual group member's flag and records ownership even before a lord/courier exists. Rejected acceptance leaves state alone. A drained manifest does not release a live lord/courier/queued loader. Teardown removes recorded provenance; departure pruning removes absent IDs/groups. The game component appends the proposal's two save labels, sorted deterministically, without changing earlier labels.

`BulkUnloadTransporterGate` provides read-only start, actor/target and toggle admission plus a transfer endpoint that rechecks live admission after the visual wait. It checks feature/flag, spawned current comp/container/map, VF exclusion, caravan/shuttle loading state, undrafted owned actor, component/inventory/empty hands, Hauling capability, native robot role and mech work type, automatic eligibility/directed activity, forbiddance and current load custody. Automatic work only originates on player-owned holds; explicit supported hold orders may override forbiddance. Passengers never enter the cargo planner. No conflict polling timestamp exists: the actual transfer endpoint reads current ownership, so the proposal's first-scan overflow and 60-tick stale permission window are absent from this seam.

Successful `InitiateLoading`/dialog acceptance, `TryRemoveLord`, cancel and Contents-tab removal hooks are installed regardless of the setting's initial value. They invalidate load probes synchronously. `TransportLoad` checks the whole live group before either same-tick memo and before constructing a job. An active loader has a top-level group guard plus a separate check immediately before depositing into its actual destination member. Turning the feature off makes all these unload blockers inactive immediately, without waiting for cache expiration. The tiny new setting has default/reset/scribe coverage; its settings-window row remains integration work.

`BulkUnloadPull` extracts selection and physical transfer from the carrier driver for reuse by the new transporter driver. It preserves no-merge inventory transfer/tagging, provides explicit corpse-policy/hands behavior, excludes passengers, and rereads source ownership/count, forbiddance, hands and vanilla/CE capacity at transfer. CE rejection uses `PlanHandsFallback` through `ApplyInventoryFit`; a massless but bulky item cannot be replanned into inventory at zero capacity. The carrier driver uses this helper and rechecks carrier permission after its delay. Its historic `hdUcibPullLoops` label and reservation/graphics/finalize logic remain unchanged. The source shrinks by roughly ninety lines while removing the duplicated selection/transfer logic from the forthcoming transporter driver.
