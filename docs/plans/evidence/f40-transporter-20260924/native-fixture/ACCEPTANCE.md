# F40 native acceptance contract

Root approved this bounded contract on 24 September 2026. The first case is `F40-TRANSPORTER-CORE`, candidate-only because this is a contributed new feature; absence from an older build is not presented as a reproduced shipped regression. No Prepare or native launch is authorized to the fixture author. Root reviews the complete fixture, controller and selected-input pins before using the protected native slot.

The harness references the installed Assembly-CSharp image SHA256 `5CF1B5BE399D5B1C9C56CA72C9D35B4ECF307FEACF5859D04AC5A1AA5926356A` (installed revision590/runtime revision591). Product compilation against reference package1.6.4518 is not native proof. Existing host identity, strict evidence, error capture, immutable copied inputs, desktop isolation and owned-process checks remain intact.

Core phases:

1. Actual native transporter gizmo and HD load/unload provider enumeration, including an enabled positive option, a missing/existing claim entry, repeated same-tick queries and a fresh cache boundary. Compare job-ID counter, RNG, complete ledger/flags/session projection, actual owners/counts and current/queued jobs before and after. Exercise non-primary group flags, feature-off dormant intent, stale map/draft/feature/manifest admission, rejected/accepted/top-up/cancel load paths and existing-manifest provenance.
2. Prioritized unloading: at least two actual cargo deliveries before the same courier returns, exact global conservation, same-def personal kept stock untouched and passenger retained.
3. Two actual haulers sharing one hold: both physically pull and deliver, each transfer names its source owner, no double pull or duplication, exact conservation and final empty hold.
4. Prioritized loading: at least two actual delivered jobs to the selected manifest, no new nearby authority, personal kept stock retained, manifest completion and cargo conservation.
5. Interruption/new queued explicit work: newer queued work precedes recovery, no autonomous drafted recovery, interrupted cargo remains accounted for and can be recovered; full-storage offers/starts produce no fake progress or repeat storm.
6. Actual delayed pull: move the selected source into another real hold before transfer, then separately start native load ownership during the wait. Neither stale selection nor stale unload intent may authorize a pull.

Each phase has named preconditions, actual observations and terminal assertions. A safe failed phase is retained and later independent phases still execute. Invalid scene ownership/conservation or failed cleanup stops dependent work. A bounded stable terminal window, whole-log review and exact fixture cleanup are required. Existing material stacks are parked non-merging with original object/ID/count/cell/rotation/map owner and restored; no background stock is silently subtracted from accounting.

The final implementation numbers the independent phases 0–9: probes/lifecycle; ordered unload with passenger; two autonomous couriers; ordered load; queued replacement and recovery; source moves to another hold during delay; native loading takes ownership during delay; storage becomes unavailable after pickup; draft while cargo is in hands; ordinary drafted first load. Phase 0 includes a native mental state started after an enabled offer, its native recovery, retained continuous offers invalidated by draft and setting changes, and a nonempty native loading-command assertion for the non-primary group flag. A real over-capacity native dialog selection supplies the rejected-load control; Core pods legitimately accept an empty manifest edit.

Every phase requires a kept count of exactly seven and global physical conservation. Direct owned unload deliveries additionally preserve the original seven-unit inventory stack. Ordinary loading and ordinary recovery (phases 3, 4, 7 and 9) use the existing quantity-based keep contract: the first courier must retain at least seven units in inventory at every observed boundary; completed deliveries/recovery must leave exactly seven total carried units. Those paths may exchange same-definition stack identity through native inventory tagging. The evidence records both the quantity result and original-stack identity, plus each actual owner and count; it never subtracts a personal-stock deficit from the conservation total.

The private quicktest environment uses healthy generated couriers and a bounded native tile-temperature input. An 80,001-tick native forecast must fit 8.5–29.5°C after a serialized-tenth mean adjustment; live outdoor/courier temperatures must remain 8–30°C. No health/stat bypass is installed. Cleanup restores the original mean, settings, parked stock and parked pawns. The disposable scene's cleared terrain, Home cells and fog are not a player-map restoration claim. All graphical execution must use `scripts/run-on-test-desktop.py` around `native-fixture/launch.ps1`; `-WindowStyle Hidden` alone is not desktop isolation.

Save/restart is a separate producer/consumer pair, not claimed by Core: producer saves during a real partially pulled/delivered operation, while another explicit transporter order is queued behind newer explicit work. Record actual job IDs, driver cargo references/counts and progress, hold/inventory/hands/ground/storage ownership, flags/session and kept count. Pin the exact generated save bytes. A fresh process loads only that copied fixture save, verifies restored identities before advancing, and requires safe delivery/recovery without duplicated pulls or lost queued intent. Inventory and hands positions are distinct saved states; no constructor-only serialization surrogate counts.

Optional acceptance remains explicit: installed CE must exercise the actual hands-only capacity fallback and shared carrier/corpse controls; a real Multiplayer session must exercise synchronized command registration/replay and equal jobs/flags/claims/cargo on both clients. Supported shuttle load/unload ownership uses the actual installed provider/DLC identity. Missing optional environments are stated as unexecuted boundaries, never simulated as passing. These legs are limited to the contribution's shared paths; this is not general transporter certification.
