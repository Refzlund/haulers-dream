## Focused controls in the same fixture

- **Failed reserve and probes:** snapshot real plans/reservations/claims/cargo, run native `CanReserve` and actual menu planning, then an intentionally impossible native reserve count larger than the spawned source stack with `errorOnFailed:false`. Require native false and exact untouched plans/ownership/cargo; do not inject a false return.
- **Incidental extra:** obtain an actual forced bulk plan before another pawn reserves one of its extras; retain that plan unmodified and admit it only after the other pawn's real reservation exists. Its original anchor may reserve, but the stale incidental extra must not cancel or retire the holder's job. This exercises the admission race that `ReserveAsManyAsPossible` previously allowed.
- **Unsupported ownership:** use a genuine non-hauling native reservation displacement and direct native job cancellation outside Reserve. Require normal native cancellation. Record replacement-driver guards from source/binding review; no foreign mod matrix is required.
- **Constrained destination:** after the ample-storage case, measure a small genuine destination with a pawn already carrying tagged surplus. Retiring one source must release only its planned units; the actual held surplus must still reduce available capacity. Do not suppress `InterruptCommittersTo` or overbook storage to make the handoff pass.
- **Determinism:** repeat the same bounded command sequence from a retained identical pre-command scene/checkpoint and compare canonical pawn/job/source/reservation/claim/cargo state at each command boundary. This is a synchronized-mutation check, not a claim of a full Multiplayer network session; final integration owns network QA.
