# F38 independent source recommendation

Source review only, 24 September 2026. No product/fixture edit, native reproduction, Prepare or completion claim. Frozen GH266 in `scoped-feedback-register.json` is the governing report: assigning another pawn one of a nearby sweep's reserved items cancels the first pawn's whole sweep. The report suggests incremental reservation as one possible remedy; the required outcome is cooperative hauling without losing the remaining first order.

## Findings that determine the implementation

1. Native `ReservationManager.Reserve` first adds the forced claimant's actual reservation, then calls `EndCurrentOrQueuedJob` on conflicting old reservations. `EndCurrentOrQueuedJob` extracts/cleans the queued job or ends the current job. Thus the old bulk driver's ordinary per-target skip checks run too late.
2. Native `ReservationUtility.ReserveAsManyAsPossible` directly calls `Reserve` on every entry with the original job. A `playerForced` bulk job can therefore force-take an incidental extra during admission. The later `CanReserve` guard in BulkHaul's decide toil does not protect this earlier call. Replace this bulk admission loop with non-forcing `CanReserve` gating for extras; retain explicit force permission only for the original slot-zero anchor.
3. The pickup plan is `targetQueueB` plus aligned `countQueue`, with a separately scribed `loadIndex`. Removing an entry shifts the cursor and can silently skip or repeat work. Index zero also controls the forbidden-primary privilege. Preserve positions: retire a relinquished entry as `LocalTargetInfo.Invalid` plus count zero, not `RemoveAt` or a promoted new anchor.
4. Zero count alone is insufficient. `StorageEvidence.AddPlannedPickups` treats missing/nonpositive counts as the whole stack, and `RouteSelection.CollectJobTargets` includes target A/B/C and both queues. Clear matching obsolete scalar anchor/scratch references as well as the relinquished B-queue slots, or explicitly teach the bulk-specific claim reader to ignore them. Invalid targets make the current evidence readers ignore the source without dropping unrelated carried cargo.
5. The current take toil already skips null/nonpositive entries, but the path/pickup pause can still be in progress. Resolve a retired current target from the driver's own next safe pre-tick boundary. Do not synchronously jump/run its next reservation from inside another pawn's `Reserve` enumeration. A cheap check of the serialized tombstone on the existing walk/pause toils is enough; stop the old path, advance once, and jump to the existing decide toil. Preserve toil count/order for saved `curToilIndex`. Future retired entries are skipped by the existing decide loop.
6. A queued nearby order need not yet have any native reservation. Only intercepting the conflicting-reservation cancellation misses that order; when admitted later, its old primary can force-take the item back. Successful explicit source reservation must also retire matching pickup entries in other pawns' queued bulk plans that have no native reservation. Preserve each `QueuedJob`, job identity, queue position, other targets and subsequent queued orders.

## Smallest coherent boundary

Use a narrow replacement of the `EndCurrentOrQueuedJob` call site **inside native Reserve**, passing the manager, forcing claimant/job, target and layer into a helper. The new reservation already exists at this boundary. The helper performs the target-specific bulk handoff only when the actual old reservation, old job and target match; otherwise it invokes the original method with every original argument. Do not patch/suppress `InterruptForced` globally. A shape-checked transpiler should either patch the complete intended call shape or retain native behavior and report an unsupported binding; no partially rewritten method.

The item-target call is the relevant path. The other two native calls concern a building's interaction cell/edifice and must retain native behavior. A wrapper can guard these out using the source/item requirement even if all three call sites share the same replacement signature. Bind and audit the exact emitted calls against this installed image before runtime acceptance.

Add a successful-Reserve postfix for the same explicit haul source to cover unreserved queued bulk plans. It runs only when Reserve returned true and the new claimant/job actually owns the reservation. Do not retire anything during CanReserve, a speculative planner/menu probe, or a failed Reserve. Restrict explicit bulk source authority to its original positive slot-zero anchor; incidental swept extras must not retire other pawns' soft queue claims. Native haul/take-inventory source orders can use their corresponding primary target, with an explicit job-shape predicate. Foreign/non-hauling jobs retain ordinary cancellation behavior.

Both paths share one idempotent bulk-plan retirement routine:

- Require a spawned source on the same map, a different old pawn, and an exact current/queued HD BulkHaul job that actually references it. Use current driver or `GetCachedDriverDirect` if needed; do not create speculative drivers.
- Retire all matching pickup slots without moving indices, and clear only matching obsolete scalar source references. Preserve unrelated queue entries, `playerForced`, workGiver/map authority, cursor, loadedAnything, nearby cargo manifest, tagged inventory, keep counts and delivery jobs.
- Release only this target's reservation for this old pawn/job. HD's pickup reservations use the default layer; do not call ReleaseAllForTarget/ReleaseClaimedBy. Native public Release has no layer argument, so validate that the matching default-layer reservation is unambiguous before using it. Unknown layered ownership falls through to native cancellation.
- Invalidate same-tick `RouteSelection` claimed-target and BulkHaul plan memos. Invalidate StorageCommitments' evidence memo/generation while retaining its rows: those rows are clamped to remaining planned pickups plus actual tagged surplus, and must continue protecting cargo already held. Do not call whole-ledger ClearCaches or DropClaim(def), which can discard legitimate carried stock.
- For active current pickup, let the existing driver's safe pre-tick recovery consume the tombstone exactly once. For future pickup, retain the cursor. For queued pickup, leave the queued job in place.
- Update pre-reservation admission to tolerate a relinquished slot-zero tombstone: reserve only remaining valid entries, with force authority still limited to original index zero. A completely retired plan can finish as an empty no-op through its normal driver path; it must not consume or reorder later user commands. A suspended job carrying cargo must still reach its normal finish/delivery behavior.

The successful postfix should iterate affected pawns deterministically by thingIDNumber and preserve their native queue order. It is an actual job mutation on the existing synchronized reservation path, consumes no Rand and requires no UI synchronization entry point. The serialized invalid-target/count tombstones avoid a new save field or process-local relinquished-target registry. Derived caches are invalidated at the mutation and rebuilt on load as usual.

Keep storage destination conflict policy separate. `CommitPlannedDestinations` can also call `InterruptCommittersTo` when a forced destination is full; a source-reservation handoff is not permission to overbook that destination. First native acceptance should give both pawns enough genuine shared storage to isolate GH266; then a focused constrained-storage control must show existing capacity/cargo protection remains intact. Do not mask a second cancellation source by broadly suppressing it.

## Bounded acceptance

Reproduce the actual old behavior with two native pawns and at least three distinct source stacks. On the candidate, hand the second pawn the first pawn's **current** source, a **future reserved** source, and an **unreserved queued** source. Preserve job IDs, queue positions and unrelated queued replacement work; show the first pawn finishes the remaining sweep and both physically deliver conserved cargo. Include an already-loaded partial cargo/keep case so the handoff cannot erase storage evidence or cargo authority.

Inspect the actual reservation before/after, target/count queues, load cursor, live driver/toil, same-tick claimed-target/evidence queries and storage rows. Negative controls: failed reservation and menu probe do not mutate; incidental forced-sweep extras do not steal; direct unrelated cancellation and foreign/non-hauling displacement still take the native path. One bound save/reload of the retired current/queued plan checks tombstones survive without revival; a deterministic command replay/state comparison covers the new synchronized mutation. These are targeted checks of the implementation, not a new compatibility matrix.
