The provider creates new sapient pawn IDs; original and converted IDs are explicitly recorded. These two converted pawns and one ordinary human become the measured actors. Generated definition component count, live `AllComps`, and `GetComp` live membership are observed. Baseline generated definitions must omit HD. If the provider/native component-count branch still exposes a fresh HD comp, physical 2+3 bulk delivery is required. If fresh lookup already lacks HD, the scene records that earlier gap and does **not** claim pre-save success. Human delivery must work. It then saves the actual converted colony with empty measured cargo and default preferences; no component/cache/serialized state is edited.

LOAD binds those saved IDs/races/map and physical state before the first loaded tick. It independently tests generated/live component absence and sends a real synchronized player command, which must not admit bulk hauling. Missing HD on both converted actors is the intended baseline failure. Setup, provider, identity, human, or causal-control failure is not reproduction.

Each original actor then physically delivers 5 units. A subsequent real 7+11 command is paused immediately after native pickup of 7; native drafting cancels its current order, the actual keep setter requests 2, and the synchronized auto-haul setter opts out.
