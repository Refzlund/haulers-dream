# F34 productive cutting source proposal

`src/LiveCutting.cs` is a single scenario for the existing admitted runtime host. Add this file to its project with the selected HD/Core references. It has no startup hook, separate DLL requirement, Harmony patch, controller, build wrapper or evidence framework.

Call `HaulersDream.F34Native.LiveCutting.Begin(map, check, emit)` once after actual player control, then call `Update()` from the existing host update loop. It returns exactly `running`, `passed` or `failed`. Call `Dispose()` from the host's terminal/timeout cleanup. `ActiveDialog` exposes only the real pre-confirmation dialog. The explicit case is `F34-LIVE-CUT`; host admission, copy protections and output ownership remain the existing host's responsibility.

The scenario reuses the mixed-boundary fixture's 31×31 disposable ground preparation, seed-42534 normally generated colonist, skill level 20, original nine plants and native crop infection. Native **Cut all blight** must mark only A/B/E/H/I. The actual `Dialog_PlanRoute` preview must contain those five original identities. The dialog is then added to native WindowStack while paused for at least one second of host updates. This allows normal game rendering and separate read-only inspection; the fixture does not count GUI frames or claim button/input delivery.

While keeping that original tick paused, it observes the actual `nextBlightPreviewCheck` advance through normal window frames and requires unchanged `cachedLegs` reference for the original five-target plan. It then explicitly removes B's Blight (fault injection, not natural healing), waits for the next native poll and requires exact A/E/H/I with rebuilt legs. Native `CropBlighted` reinfects the same B plant; its new Blight is added to owned cleanup. The next native poll must restore the original five targets with another rebuilt legs reference. B's original cut designation must remain intact. No fixture refresh call, patch or counter drives these observations; only the initial setup calls `RefreshPlanIfNeeded`. The 120-second overall bound covers missing polls. After those checks it calls the existing confirmation body programmatically, removes only its owned dialog, and verifies the five queued native CutPlantDesignated jobs.

Normal native ticks then execute the route. No productive outcome uses direct plant destruction, Kill, DoWork, toil execution or manual tick calls. Update records observed current native JobDriver_PlantCut/job/target identities, changes to the queue and destruction of the original infected plants. A completed job requires that exact original queued job to have been observed current, to have left current/queue, and its original plant to be destroyed. This is an observed completion transition; the fixture does **not** claim to observe EndCurrentJob's condition. Success requires all five completed transitions before cleanup and healthy C/G still alive without orders.

After explicit route submission, only automatic PlantCutting priorities are temporarily disabled for the map's colonists. The existing forced queue remains intact. This prevents later automatic work from consuming D/F's independent designations, whose exact objects must remain intact while the scenario runs. All captured priorities are restored. Closing the real dialog normally persists its route preferences; cleanup restores the captured dictionary object and original entries, and writes those settings through the normal product method. The captured native speed is also restored. Owned jobs, dialog, preview, actor, plants, blight and zone are retired; disposable terrain/home/fog changes follow the previous fixture and are not a claim of restoring the entire fresh map.

The bound is 1,800 running ticks and 120 seconds overall, including the preview. The actual pinned native Blight starts at severity 0.2, adds 1/30 every 2,000-tick TickLong interval, reproduces only from severity 0.28 and harms plants only after 60,000 ticks. Within this bound, ordinary initial blight cannot supply the observed destruction outcome or spread to C/G. A missing/abandoned job, unhealthy C/G, changed independent order or timeout fails the scenario; cleanup destruction cannot turn it into a pass.

This is source authored for review, not a passed run. Product code and prior native results are unchanged. Root owns host integration, build, rendered-preview/live-refresh observation and actual execution. No game, UI, input, build or controller was executed while authoring this proposal.
